# 同样的 WER，不同的伤害：一个关于转写错误类型与低成本闸门的探索性负结果

**范围声明**：42 条构造的口语指令、两个 Qwen2.5 模型（3B-Instruct fp16、7B-Instruct-AWQ）、文本层错误注入、提议的（未执行的）工具调用。
所有数字都是 **EXPLORATORY**；三个 pilot 均预注册，判定按预注册规则；主张措辞按 `/result-to-claim`（gpt-6-sol，session 01a0d470…）的判定收窄，见 `../CLAIMS_FROM_RESULTS.md`。
本文不主张任何关于真实 ASR、真实执行后果、其它模型族或"便宜闸门普遍失效"的结论。

## 一句话

在一个用 42 条构造指令和两个 Qwen 模型的探索性文本注入 pilot 里，同 WER 的否定删除比功能词删除造成多得多的错误提议调用；两种确认提示很少澄清单词错误；一个可选布尔调用过滤器以近乎全体确认合法正向请求为代价换来高否定拦截。

## 问题

级联语音 agent（ASR → LLM → 工具）里，WER 只数错字。我们想知道：**把 WER 固定**（同一条指令、恰好一个词级编辑）时，
错误的**类型**对提议动作的伤害是否不同；两种低成本闸门——"不确定就确认"的系统提示、oracle 说话人标签——各能挡住哪一类。
文献里没有人做过这张"类型 × 闸门"表（综述见 `../idea-stage/IDEA_REPORT.md`，51 篇 arXiv ID 逐条核实）。

## 设计

- **卡片**：42 条指令，每条恰有一个否定词，删除后恰翻转 gold 调用里的一个可选布尔参数；gold 与"忠于转写的翻转调用"由构造决定。23 个工具 schema，每卡带 1–2 个干扰工具。
- **单编辑条件**（逐条 WER = 1/L，四者严格相等）：`neg_drop` 否定词删除 / `func_drop` 功能词删除 / `content_sub` 内容词近音替换 / `other_1w` 旁人单词句尾插入 / `other_1w_mid` 同一词句内插入。
- **剂量条件**（WER ≈ 0.38）：`other_intent`（3–6 词带有效意图的旁人片段）/ `other_chatter`（无意图闲聊）。
- **闸门**（系统提示）：`none`；`confirm`（点名可能的错误类型）；`confirm_generic`（只说"不确定就问"）；`spktag`（oracle `[speaker 1]/[speaker 2]` 标签）；`confirm_optbool`（规则：把任何可选布尔设为 true 前必须确认）。另有离线的确定性版本 `wrapper_optbool`。
- **P0c 的正向镜像卡**：42 条"用户确实要那个 true"的指令（gold = 原卡的翻转调用），用来测规则的代价。
- **打分**：预注册的严格打分（所有 gold 参数须匹配）与事后宽松打分（DEVIATION：函数名 + 布尔/整数/枚举须匹配，自由字符串不计）。两者都报；严格版把 clean 条件 28.6% / 16.7% 的调用因"four o'clock"≠"4 o'clock"之类判错，宽松版无法可靠测量实体替换的伤害。
- **统计**：WA = 错误动作率（WRONG_ACTION + FLIPPED + EXTRA_CALL），CF = 确认率；按卡片配对 bootstrap 95% CI；temperature 0。
- **算力**：Colab T4，四次会话，$0。冻结哈希与 codex session 见各 PREREG / IDEA_REPORT。

## 结果（宽松打分；n = 42/格；严格打分表见 `../pilot/RESULTS_P0*.md`）

### 表 1  同 WER 下的错误动作率（无闸门）

| 条件 | WER | 3B WA | 7B WA |
|---|---|---|---|
| clean | 0 | 7.1 | 2.4 |
| neg_drop | 1/L | **97.6** | **97.6** |
| func_drop | 1/L | 14.3 | 4.8 |
| content_sub | 1/L | 19.0（严格 95.2） | 9.5（严格 92.9） |
| other_1w | 1/L | 21.4 | 9.5 |
| other_1w_mid | 1/L | 14.3 | 11.9 |
| other_intent | ≈0.38 | 28.6 | 21.4 |

预注册 H2：WA(neg_drop) − WA(func_drop) = **+83.3pp [71.4, 92.9]**（3B）、**+92.9pp [85.7, 100]**（7B）。
这是构造决定的幅度（否定删除必然翻转 gold），不是发现；它说明的只是"同一个 WER 下伤害可以差一个量级"。

### 表 2  确认闸门的确认率

| 条件 | 3B confirm | 3B generic | 7B confirm | 7B generic |
|---|---|---|---|---|
| clean（误确认） | 0.0 | 0.0 | 0.0 | 0.0 |
| neg_drop | 0.0 | 0.0 | 9.5 | 2.4 |
| func_drop | 0.0 | 0.0 | 2.4 | 2.4 |
| content_sub | 0.0 | 0.0 | 0.0 | 0.0 |
| other_1w | 4.8 | 2.4 | 9.5 | 4.8 |
| other_1w_mid | 0.0 | 0.0 | 2.4 | 2.4 |
| other_intent | 31.0 | 28.6 | 21.4 | 16.7 |
| other_chatter | 16.7 | 14.3 | 23.8 | 16.7 |

预注册 H1（CF(other_1w) − CF(neg_drop) ≥ 25pp）：**+4.8pp [0, 11.9]**、**+0.0pp [−11.9, 11.9]**，不成立。
动作级差分之差（confirm 对 other_1w(_mid) 的 WA 降幅 − 对 neg_drop 的降幅）：3B other_1w +2.4 [0, 7.1]、other_1w_mid −4.8 [−11.9, 0]；7B −7.1 [−16.7, 2.4]、−9.5 [−19.0, −2.4]。全部远低于 25pp。
7B 在 neg_drop 下的 4 次确认都问在被翻转的参数上（例如"also carbon copy your manager?"）——个案观察，n = 4。

### 表 3  oracle 说话人标签（other_intent 的 WA）

| | none | spktag | 降幅 [95% CI] |
|---|---|---|---|
| 3B | 28.6 | 26.2 | +2.4 [−11.9, 16.7] |
| 7B | 21.4 | 9.5 | +11.9 [0, 23.8] |

预注册 H3（≥ 30pp）不成立。clean 上 spktag 未增加错误动作（+0.0 / +2.4pp）。

### 表 4  可选布尔参数确认规则（P0c）

| | 3B prompted | 3B wrapper | 7B prompted | 7B wrapper |
|---|---|---|---|---|
| 挡住 neg_drop（CF） | 0.0 | 97.6 | 2.4 | 97.6 |
| CF(clean，42 否定卡) | 0.0 | 4.8 | 0.0 | 2.4 |
| CF(clean_pos，42 正向卡) | 0.0 | 97.6 | 0.0 | 100.0 |

预注册判定（挡住 ≥ 60% 且合并 CF ≤ 30%）：四格均 CLOSE。51.2% 是人为 1:1 配比下的数字，不是部署代价。

## 数据支持什么

1. 在 42 条构造指令上、逐条 WER 相同时，删除否定词在两个 Qwen 模型上产生的错误提议调用远多于删除功能词。
2. 在这两个模型上，所测的两种确认提示对构造的单词错误（含否定删除）很少请求澄清，clean 上零误确认；预注册的"旁人插入 − 否定删除"确认率差不存在。
3. 所测确认提示在较长的旁人片段上更常发问；这些片段的 WER 也高得多——长度、WER、位置、内容一起变化，不能归因于单一因素。
4. oracle 说话人标签未达到预注册的 30pp 降幅（2.4pp、11.9pp）。
5. 在成对卡片上，提示版可选布尔规则几乎从不挡住否定删除；确定性版挡住 97.6%，但把 97.6–100% 的合法正向请求也变成确认。成对卡片的 gold 调用完全相同，所以任何只看调用本身的规则分不开二者。

## 数据不支持什么（报告里不写的）

- 关于"通顺语义错误（含实体替换）"的一般性结论：实体替换的伤害在两种打分器之间未解决（严格 93–95%，宽松 9.5–19%），需要盲判自由文本参数才能定。
- "便宜闸门普遍失明"；"某模型忽略标签"（3B 的输出在 spktag 下有变化，NO_CALL 6/42 → 4/42）；把 51.2% 当部署代价；任何关于真实 ASR 输出或真实执行后果的说法。

## 偏差与诚实记录

- 打分器：预注册的严格打分对自由字符串过严，事后加宽松打分并两者并报（DEVIATION）。
- P0c 第一次运行因 Colab 客户端 50 分钟无输出超时作废（作业脚本改为流式输出后重跑，冻结文件哈希未变）。
- 卡片由执行者手写，未经盲检；单一模型族；仅提示级闸门；文本注入而非真实 ASR。
- 外部评审历史：查新 PROCEED WITH CAUTION（7/10、6/10）、外部评审 PROCEED（6/10）、方案评审 REVISE（5.5/10）、result-to-claim partial；均 gpt-6-sol high。
